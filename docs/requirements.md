# jdp-wiki 产品需求

更新：2026-10-13。以下为待实现要求，现有实验不等于功能验收完成。

## 条目与知识复用

条目包含稳定 ID、标题、英文名／缩写／别名、分类、一句话定义、正文、例子、适当图示、区别与边界、来源及核验日期、相关条目、状态与版本。按条目类型裁剪字段，避免无关空章节。

- 同义名称指向同一条目；同名异义创建消歧入口。例如 TTL 区分 Turtle 与 Time To Live。
- 各项目的公开通用术语逐项提炼、审核后归入 Wiki；原项目保留链接和必要的场景说明，逐步消除重复定义。
- 项目私有术语、内部实现、客户概念留在项目自身；同名概念以作用域区分，不能强行合并。
- 引用优先采用稳定 ID／链接；需要固定口径时记录版本。正式 API 和版本引用方式待接口设计确认。
- 不自动搬运所有项目文档；迁移前核对来源、授权、敏感性和独有信息，失败时保留原内容。

## 首版功能与验收

| 功能 | 要求与验收口径 |
| --- | --- |
| 阅读导航 | 条目页、目录、分类、别名、相关条目和消歧可访问；移动端内容可读 |
| 搜索 | 支持标题、别名、全文与分类过滤；用样本集验证中文、缩写和同名异义命中正确条目 |
| 编辑 | Markdown 草稿、预览、来源和图片管理；未发布草稿不可从公共搜索访问 |
| 发布与版本 | 草稿→审核→发布；保存差异、操作者与时间，可回退、撤回；撤回同步搜索和缓存 |
| 质量检查 | 提示缺来源、疑似重复、断链和过期条目；提示由编辑确认，不自动删除正文 |
| 纠错反馈 | 读者提交建议，编辑可受理、修正、关闭并保留处理记录 |
| 权限审计 | 区分读者、编辑、审核者和管理员；后端执行权限，记录发布、回退及撤回操作 |
| 备份恢复 | 正文、元数据、版本及附件可备份；完成一次恢复演练并核对引用有效 |

首版可以由同一维护者兼任编辑和审核者，但须保留显式确认步骤。匿名反馈需限流与防滥用；不允许匿名直接发布。

## 示例与验收数据

用约 20～30 条试点样本覆盖 RDF、OWL、SPARQL、Turtle、Time To Live、产品条目、图片和易变信息。数量为建议，重点是流程覆盖。

例如项目 A、B 均使用 RDF：共用 Wiki 定义与示例；A 的内部“客户风险等级”留在 A。搜索“TTL”展示两个含义；编辑修正 RDF 后生成新版本，项目固定版本引用仍可追溯。

## 后续与约束

可信贡献者、多语言、语义检索、公开 API 和 RAG 按需求扩展。AI 可提取术语、生成草稿和提供来源线索，须核验后人工发布；RAG 仅使用已发布且授权的内容，返回来源与版本。

软件许可与内容许可分别确定；图片、译文、外部文章分别核对授权。不自动同步私人知识库，不把未经核实的 AI 回答作为正式知识。
